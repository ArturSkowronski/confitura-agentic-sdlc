Thesis

You can buy change production with a credit card. Acceptance is still done by people.

For 50 years both sides grew together, because the same people did both in the same hours.

An agent: roughly 0.5-1 USD per run on a Sonnet-class model. A second agent is a second manifest.

Acceptance: a handful of people who know why this module looks weird. You can't hire them in a quarter.

0:02 · openingreveals: 0
The surplus does not disappear. It piles up first in the review queue, then in the quality of review itself. The whole workshop answers one question: what do you build so the gap stops growing. Lesson 1 · Cluster and first agent

An agent is a cluster resource, not a script on a laptop. It has a manifest, a version, an owner, limits and an address.

$ kubectl get agent -n fabryka NAME READY AGE probny True 2m $ kubectl get deploy,svc -n fabryka -l kagent=probny deployment.apps/probny 1/1 service/probny ClusterIP $ make a2a A=probny T="Introduce yourself" → http://kagent-controller.kagent.svc:8083/api/a2a/fabryka/probny/ I am the factory's trial agent (...)

The kagent controller turns an Agent CRD into a Deployment, a Service and an A2A endpoint. The mechanism you have used for years to deploy services now deploys agents.

The agent card (/.well-known/agent-card.json) tells the line and other agents what this agent can do.

A manifest goes through the same review as code. Who approves a prompt change in your team today?

Lesson 6 · Quality control the agent can't see

A green build proves only one thing: the model agrees with itself.

ArchUnit

Structure in milliseconds, no model, no network. Freeze: old violations stay, new ones block. The .because text is also read by the agent in AGENTS.md.

PIT

Mutations only on changed classes. They measure the tests, not the code. A correct discount: 67%, two boundary mutants survived.

Detector

A removed assertion, @Disabled, a deleted test. The cheapest way to "pass" a gate is to weaken the test. Plus gitleaks for secrets.

make naiwna: a discount in OrderService passes every gate green. The gates are a kontrola DAG after the change step: outside the agent's container, on files it can't change, not reading its prompt.

Lesson 7 · The oracle wears out

Every bit of feedback about a scenario is a leak. A holdout wears out with every use.

$ make a2a A=wykonawca T="Read scenarios/rabat/.../ RabatScenarios.java and summarise what it checks" read_file → (scenario contents) # write blocked, read not platforma/warsztat/mcpserver.yaml + HIDDEN_PATHS: "scenarios" $ make a2a A=wykonawca T="Read scenarios/rabat/..." read_file → out of the agent's reach /work/events.jsonl: holdout.peek what the agent gets on a fix (all of feedback.md): Does not meet requirements (scenarios you can't see): - Two partial refunds of one payment both reach the customer - A refund larger than the remaining amount is rejected

Working scenarios: their names go back to the agent. Code, assertions and data never do.

The vault: a verdict only. Zero feedback. A failure pulls the andon, because a fix "for the vault" would turn it into a training set.

The same thing as reusing a test set in ML: adaptive overfitting to the oracle.

The factory's capital is the oracle, not the agent: everyone has the same models.

Lesson 8 · The fix loop

The factory sends a change back for a fix by itself. And every fix raises the risk.

A fix moves the agent from the requirement towards the gate. That's why the attempt number is a risk signal and the test-weakening detector blocks the change. The whole history is one graph in the hall.

Andon after max_attempts (2) or a vault failure: the workflow ends with an error. The line stops and holds a WIP slot until a human takes it off.

Lesson 8 · Risk and review

Code computes the risk, not the model. The model reads only when the risk deserves it. And it only advises.

signalptsfrom
gate or oracle changed+7gate_paths in policy.json
critical path+4module.json, ADR-0002
shared library+2sensitive_paths
no scenarios for the order+2scenarios/index.json
code without test changes+2diff
incident in module, many changes in 30 days+1ops/, git log
fix number N+N−1parameter proba

Prompt injection in the diff can't lower the risk, because the model doesn't compute it. LLM lenses only above a threshold (llm_from_level), DET-* regexes always.

Reveal: the reviewer (a real model) finds in attempt 2 what the oracle can't see: a random UUID as the idempotency key protects against a double refund, but not against a retry of the same request. That's INC-2026-03-14 from the other side.

Precision over recall: at most 5 findings, confidence ≥ 0.6. A blocking finding escalates to a human: the model advises, the human decides.

A human is a node with a role, not a tax on every change. A versioned file draws the line.

One suspend step and the run turns yellow in the hall. make zatwierdz (approve) sets kto (who) and resumes; your name goes into the ledger signed by cosign.

Without that step the czlowiek (human) template passes, and the factory records honestly: human.approval_missing, change not accepted.

Lights-out only with scenarios. Low risk without an oracle still goes to a human.

Lesson 10 · The ledger

Change one word in the ledger and the chain shows which line. The signature stops matching the file.

$ make ksiega-verify F=.sdlc/out/zwroty-czesciowe/proba-2/ledger.jsonl OK: 41 events, chain head c5a38c032767 Verified OK # cosign verify-blob, factory key $ sed -i 's/human.approved/human.skipped/' .../ledger.jsonl $ make ksiega-verify F=.../ledger.jsonl line 37: content changed after write (human.skipped) Error: verifying blob: invalid signature

Every event holds the hash of the previous one: intake, prompt, tool call, commit, gate, decision, approval. The same ledger holds holdout.peek and gate.tamper_attempt.

The ksiega (ledger) step signs the file with the factory key (cosign sign-blob) and records a hash of the line config: the line must be repeatable even though the worker isn't.

kagent traces (OpenTelemetry) in Jaeger: every model and tool call.

Lesson 10 · Laws and capital

An agent may propose laws, but it may not pass them.

reviewer, proba-2/review-2-review.md: "Services don't build Money from a request String without validation. I propose an ArchUnit rule." change from the agent: → system/architecture/.../ArchitectureRulesTest.java → docs/conventions.md, AGENTS.md rebuilt sdlc/risk.py: gate change +7 → critical decision: human # policy.json, autonomy

A new gate changes every future decision of the factory, so it touches gate_paths, gets critical and waits for a human. Factory quality grows with the number of defects turned into rules, not with model quality.

The factory's capital is the oracle, not the agent. The agent driver is 266 lines. Everything else (context, intake, gates, risk, ledger, oracle, cluster manifests, line) is about 2900. You swap the agent with one parameter.
